# Pending native Save preview provider

The same original Prepared Save service and PreviewStore policy now compose
retained document publication with a private preview FileEffects receiver.
Actual rename, copy and source retirement publications stay in the same pending
native operation. Copy continuation is live ownership, never reconstructed JSON.
All results retain original autosave and preview writer pauses. No public
command, model hand, post-dispatch release or active-app adoption is introduced.

The original body chooses rename, then copy on error, then source removal only
after copy success. Physical source removal is preserved source-side retirement.
Existing targets and unindexed data remain. Worker probes observe the original
pause epoch and cannot acquire, resume or dispatch. Directory mkdir calls and
observed identities record partial effects but explicitly confer no custody.

Credits cover preview-only source archive, two destination payloads, records
and missing parents. Each physical role consumes its bound once; current free
space must retain the reserve and unassigned work. Complete document/backup/
preferences budgets, current Root and overwrite grants, namespace and created-
directory custody, aggregate reconciliation and cold recovery remain required.
Storage specs do not authenticate UUID: the trusted I/O checker must do so.

Aliased catalog inodes and callback sets above the unchanged native event bound
refuse before dispatch. Full causal alias validation and scalable complete
journaling remain open. Nested missing source/target contexts, read-only error
parity, actual cross-volume operation, physical power loss and large-volume/
cadence acceptance remain unproven. Tests use generated bytes; a real mkdir
collision exercises original rename-error/copy/retirement, and does not prove
cross-volume acceptance. The full original integration goal remains open.
