# Save lifecycle on the original native worker

Begin, status and cancellation use the existing exclusive SessionWorker. The
actual Session and native Save key move to that worker; the display projection
retains neither. A separate task wait control observes Stop on the original
checks. It cannot cancel a native operation, authorize files, resume workers or
extend the original planning delivery or publication deadline.

The existing AgentOperationControl carries one live Save wait. The bounded
loopback control server exposes engine.cancelSaveOperationWait for that exact
job/operation. It changes only wait atomics, independently of the Session and UI
queue. Completion clears only that same task identity. A late Stop never means
the original native Save was cancelled.

The desktop retains at most one exact cancellation intent while a Save task is
running. It requests Stop, restores the real Session, then sends that intent
through the same worker and original native cancellation routine. Competing
editing input is refused. The pending Save view has the existing Stop automation
id; a close request cannot discard a still-held native Save owner.

Native publication, current filesystem custody, durable accepted-Send and full
effect receipts/restart reconciliation remain unfinished. These private lifecycle
changes add no encoder, file publisher, general model command, installed rollout
or claim of full performance/physical acceptance.

A headless socket regression holds the original worker at its existing completion
callback after native Save begin, queues a real status call with that same key,
and sends Stop through the actual desktop TCP handler while UI cancellation is
queued. Wrong/malformed references do not stop it; exact Stop bypasses the UI
queue and cannot settle the held native owner. The original queued cancellation
runs only after the same Session returns. File bytes and project identity stay
unchanged. This adds no production hook, executor, GUI launch or publication.


The original pending Save now has a finite `agent.prepareProjectSaveRecovery`
read with the same closed job/operation correlation and SessionWorker wait/Stop.
It requires the actual original native key, persistence SavePause and preview
WriterPause; JSON/status cannot recreate them. It uses the SAME original native
history graph/editor/persistence snapshot encoder. A complete opaque frame stays
private in the actual pending owner, with full original32MiB history /80MiB
complete-snapshot bounds. Repeated reads validate that same frame and real files.
Prepared and actual post-dispatch after-basis reads are distinct; unknown or
changed after-state refuses while preserving the owner. Read cancellation never
claims native cancellation or resumes a worker. A fresh read budget cannot renew
the original Save45s planning/publication lifetime. No file is staged, published,
restored or adopted by this preparation; actual durable publication/capsule,
whole effects/native-after reconciliation and guarded release remain required.

The same owner retains at most two complete frames: the actual before-dispatch
frame and a separately validated actual after-dispatch frame. Preparing the
latter never evicts or blesses the former as current. Both remain private native
values; their descriptive receipts cannot recreate either owner or a startup.

Private recovery-record composition (not a public stage command)

Complete native frames can now prepare an exclusive record using the original
actual saved Root parent, real directory descriptors and the SAME pending Key.
The original retained directory/hash services and atomic byte writer are shared.
The byte writer checks each actual write and the file fsync. Files remain0600;
existing targets/candidates and changed parents/inodes refuse, with no cleanup or
replay. The original planning job lifetime is checked at every I/O, so a fresh
recovery read cannot renew the45-second Save write budget. Before the exclusive
link, the complete original native persistence/file basis is revalidated. Both
physical before/after frames and their private owners can be retained separately.

No new RPC or model tool exposes publication. The managed accepted-Send owner
still needs to durably bind the complete physical intent and actual current
filesystem admission before a public stage call can be wired. These files and
receipts do not complete a native Save, release workers, import a Key, authorize
startup, or prove pending/partial application-capsule capture or cold restore.

The final pre-link check fences the exact complete candidate generation, even
after the last controlled mutation boundary. The own hard-link ctime change is
handled separately; byte count, mtime, identity and complete content must agree.

Finite physical-intent preparation and inspection

agent.prepareProjectSaveRecoveryRecord takes the same original job/operation,
retained capture UUID and exact reserveBytes. It acquires the actual native
private Record behind that frame, without any file creation.
agent.readProjectSaveRecoveryRecord reads the same retained descriptor and full
current physical observations. Both use the original SessionWorker, finite
classifier and independent wait Stop; malformed/foreign inputs never recreate
a Key or Record. Before-frame inspection remains historical after the actual
Save reaches its distinct native after phase. Every authority/resume flag is
false. No publication command or model tool is introduced by these calls.

agent.publishProjectSaveRecoveryRecord takes the same job/operation/capture plus the complete previously prepared intent. It publishes only the existing private Record under the original native Key, parent identity and planning lifetime, via the original SessionWorker/wait Stop. Unknown fields and mismatched intents fail before file I/O. A single attempt is retained, including partial/error outcomes; readProjectSaveRecoveryRecord observes it without replay or native completion. The manager must durably journal complete intent before invoking publication.

The same original operation now supports a private complete effect observation: immutable original plan, actual native body return versus caught panic and postflight failure, all call-return events, full document/preview/retirement/directory/admission/credit receipts and fresh original physical inspections. It preserves explicit unknown-after state and inspection errors, never retries, cleans up, publishes or releases workers, and refuses rather than truncating a complete32MiB observation. Native memory snapshots remain the original SaveRecovery before/after frames; descriptive receipt reads do not replace them. Public dispatch/reconciliation and SDK/journal integration remain unfinished.

The finite agent.readProjectSaveEffects command uses the same original SessionWorker/Key and independent wait Stop. Complete32MiB observations get a separate64KiB correlation-envelope allowance, never a smaller payload or renewed write lifetime. The envelope binds original job/operation, actual saved Root scope, native session and PID. Unknown-after remains explicit and does not require a fabricated recovery frame. Capability projectSaveEffectsRead requires the original worker and independent transport. No dispatch, reconciliation, rollback or worker release is added.

## Retained complete file admission

The internal Save service can now retain its complete original file provider before dispatch. `prepare_dispatch_files` owns the original native plan, document and preview frames, directory frames, shared allocation ledger, and initial demand. `dispatch_prepared_files` consumes those exact objects after rechecking the original operation, session, directories, bytes, file generations, volume and credit conditions. It does not capture a newer destination or rebuild the plan. The existing immediate internal path delegates through these same functions.

The bounded admission description is observational only. It cannot recreate a native operation or grant overwrite, file custody, free-space reservation, completion, startup, or worker-release authority. Stop or a failed check before dispatch leaves the original operation and worker leases held; partial native publication retains the existing receipts and explicit after-state. Public dispatch, durable accepted-Send binding and complete reconciliation remain separate unfinished integration work.

## Native retained admission lifecycle

`agent.prepareProjectSaveAdmission` binds explicit root/device/reserve policies and the complete original file provider to the same live Save key and original before-frame capture. The actual native private before-frame record must first be physically published and match a fresh inspection. A capture attempt is installed before work begins: failure, Stop or panic cannot recapture a later target. Repeated preparation must match the same policy and revalidate the same original frames and original write lifetime.

`agent.readProjectSaveAdmission` returns that retained descriptive state without capturing files or renewing write time. Both calls use the original SessionWorker and independent wait Stop. The original32MiB admission budget remains intact; the separate complete header has an explicit512KiB bound for up to16 full root paths and correlation fields. Neither command publishes project files, dispatches Save, releases workers or grants custody/overwrite authority. Typed SDK transport, complete journal/archive capacity and public guarded dispatch remain unfinished; the new commands are not advertised as an SDK capability until that integration exists.

The typed SDK integration advertises `projectSaveAdmissionRead` only with actual native worker, independent wait Stop and original recovery-publication support. The headless TCP examples route both new lifecycle commands through that same worker. The finite512KiB header allowance is separate from the original complete32MiB admission body; other reply limits are unchanged.
